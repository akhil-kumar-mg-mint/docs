Money has arrived and the payment is sitting in `ACTION_REQUIRED`. To get it settled you tell us who paid, what for, and attach the paperwork.

Four calls, in order.

<Info>
  New to the rules? Read [LRS & Compliance](/integration-guide/v3/web-integration/lrs-compliance) first. This page is the API walk-through.
</Info>

<Note>
  **PSPs must send `X-Merchant-ID` on every call here**, naming the sub-merchant the payment belongs to. LRS is always scoped to the sub-merchant, never the PSP.
</Note>

## 1. Verify the PAN

The buyer is identified by PAN, not by whoever the bank says sent the money. This checks the PAN against income-tax records and matches the name and date of birth.

Do this first. A bad PAN is a guaranteed rejection later, and you cannot quote or submit until it passes.

```bash
curl -X POST 'https://api-pacb-uat.eximpe.com/pg/pan/verify/' \
  -H 'X-Client-ID: <client_id>' -H 'X-Client-Secret: <client_secret>' \
  -H 'X-Merchant-ID: <sub_merchant_id>' \
  -H 'Content-Type: application/json' \
  -d '{ "pan": "ABCDE1234F", "name": "John Doe", "dob": "1990-01-01" }'
```

A failure returns `verified: false` and a `reason` — `NAME_MISMATCH`, `INOPERATIVE_PAN`, and so on. Sort it out with the buyer before you go further.

## 2. Quote the tax

Tell the buyer what they owe **including tax**, before they pay. This returns the TCS due and the total to collect.

Quoting reserves nothing and costs nothing, so call it as often as you like.

```bash
curl -X POST 'https://api-pacb-uat.eximpe.com/pg/lrs/quote/' \
  -H 'X-Client-ID: <client_id>' -H 'X-Client-Secret: <client_secret>' \
  -H 'X-Merchant-ID: <sub_merchant_id>' \
  -H 'Content-Type: application/json' \
  -d '{ "pan": "ABCDE1234F", "amount": 1200000, "purpose_code": "S0305", "tcs_threshold_breached": false }'
```

The `purpose_code` must be one your account is enabled for.

## 3. Upload the documents

Upload each one before you submit. They are not tied to a payment, so you can do this whenever you have them. Each upload returns a `ref` you pass in the next call.

This is `multipart/form-data` — a `file` and a `type`.

```bash
curl -X POST 'https://api-pacb-uat.eximpe.com/pg/lrs/documents/' \
  -H 'X-Client-ID: <client_id>' -H 'X-Client-Secret: <client_secret>' \
  -H 'X-Merchant-ID: <sub_merchant_id>' \
  -F 'type=offer_letter' \
  -F 'file=@offer_letter.pdf'
```

Which `type` values you need depends on the purpose code — see the [document table](/integration-guide/v3/web-integration/lrs-compliance#purpose-codes-and-documents).

## 4. Submit

Send everything else: who paid, what for, the invoice, the declaration, the tax you collected, and the document `ref`s.

We check the declaration, the documents, that the sender's name matches the PAN, and that the money adds up. Then we post it to the buyer's LRS counter and move it on.

```bash
curl -X POST 'https://api-pacb-uat.eximpe.com/pg/lrs/verify/' \
  -H 'X-Client-ID: <client_id>' -H 'X-Client-Secret: <client_secret>' \
  -H 'X-Merchant-ID: <sub_merchant_id>' \
  -H 'Content-Type: application/json' \
  -d '{
    "payment_id": "PAY_1a2b3c4d5e",
    "purpose_code": "S0305",
    "remitter": { "pan": "ABCDE1234F", "name": "John Doe", "dob": "1990-01-01", "relation": "SELF" },
    "invoice": { "number": "INV-2025-0091", "date": "2025-07-01", "amount": 1200000 },
    "address": { "address1": "12 MG Road", "city": "Bengaluru", "state": "Karnataka", "pincode": "560001" },
    "contact": { "email": "john@example.com", "mobile": "9876543210" },
    "tcs": 4000,
    "declarations": { "resident_in_india": true, "lrs": true, "tcs": true, "source_of_funds": true },
    "documents": [ { "type": "offer_letter", "ref": "<ref-from-step-3>" } ]
  }'
```

You get back one of three outcomes:

| `status` | What it means | What you do |
| :--- | :--- | :--- |
| `under_review` | Everything passed. Posted to the LRS counter, waiting on the bank. | Nothing |
| `action_required` | Something is missing. Check the `missing` array and the `outstanding` amount. | Fix it and submit again |
| `on_hold` | Needs a person — usually the sender does not match the PAN. | See [What we check](/integration-guide/v3/web-integration/lrs-compliance#what-we-check) |

<Warning>
  If `relation` is anything other than `SELF` — a parent paying for a student, say — you must also send `primary_person` with the student's name, date of birth, and passport number.
</Warning>

<Info>
  Topping up an earlier payment? Send `linked_payment_id` and a `reason` (`REMAINING_AMOUNT` or `TCS_PAYMENT`). `reason` only works alongside `linked_payment_id`.
</Info>
