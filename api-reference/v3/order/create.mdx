## Overview

Create Order is the first step in the payment flow. You send the buyer, product and invoice details from your backend, and choose how the payment is collected with `collection_mode`:

- **Hosted Checkout** (`hosted_payment`) returns a `session_id`. You hand it to the EximPe JS SDK, which opens EximPe's payment page.
- **S2S UPI Intent** (`s2s`, `upi_flow_type: "intent"`) returns an `intent_uri` that you use to open the customer's UPI app.
- **S2S UPI Collect** (`s2s`, `upi_flow_type: "collection"`) sends a payment request to the customer's UPI ID (`vpa`), which they approve in their UPI app.

All three return an `order_id`. A successful create returns `201 Created`.

| Environment | Base URL |
|---|---|
| Sandbox | `https://api-pacb-uat.eximpe.com` |
| Production | `https://api-pacb.eximpe.com` |

### Headers

| Header | Required | Value |
|---|---|---|
| `X-Client-ID` | Yes | Your Client ID, from Developer Settings in the merchant dashboard. |
| `X-Client-Secret` | Yes | Your Client Secret. Keep it on your server. |
| `X-API-Version` | No | Optional. Send `3.0.0`; the response echoes it back. It is not a credential. |
| `X-Merchant-ID` | PSPs only | The sub-merchant the order is for. Required when you authenticate as a PSP; merchants using their own credentials leave it out. |
| `Content-Type` | Yes | `application/json` |

<Warning>
  Create orders from your backend only. The request carries your Client Secret, so never send it from a browser or a mobile app.
</Warning>

## Hosted Checkout, S2S UPI Intent and S2S UPI Collect

| | Hosted Checkout | S2S UPI Intent | S2S UPI Collect |
|---|---|---|---|
| `collection_mode` | `hosted_payment` | `s2s` | `s2s` |
| `mop_type` | Optional. Limits the payment page to one payment method; `card` offers both credit and debit cards | Must be `upi` | Must be `upi` |
| `upi_flow_type` | Not used | Must be `intent` | Must be `collection` |
| `vpa` | Not used | Not used | Required. The customer's UPI ID |
| `buyer.ip_address`, `buyer.user_agent` | Not used; EximPe captures them on the payment page | Required | Required |
| `return_url` | Optional. Where the customer lands after paying | Not used; the customer is not redirected | Not used; the customer is not redirected |
| `upi_expiry_minutes` | Not used | Optional. Minutes the customer has to pay, 5–20 (default 5) | Optional. Minutes the customer has to approve, 5–20 (default 5) |
| Returns | `order_id`, `session_id` | `order_id`, `intent_uri`, `expires_at` | `order_id`, `message`, `expires_at` |

`collection_mode` has no default. Leave it out, or send another value, and the request is refused with `{"collection_mode": "Invalid collection mode"}`.

S2S UPI must be enabled on your account; it covers both Intent and Collect. See the [S2S UPI Intent](/integration-guide/v3/web-integration/s2s-upi-intent) and [S2S UPI Collect](/integration-guide/v3/web-integration/s2s-upi-collect) integration guides for the end-to-end flows.

## Request Parameters

Fields not listed as required are optional. "Conditional" means the field is required only in the stated case.

#### Top-level

| Name | Type | Required | Description | Constraints |
|---|---|---|---|---|
| amount | string | Yes | Amount to collect, in rupees. | Decimal string such as `"1000.00"`; a JSON number is also accepted. More than two decimal places are rounded to two — `1000.456` is charged as `1000.46`. Greater than 0 and at most 10,000,000.00 |
| currency | string | Yes | ISO 4217 currency code. | `INR` |
| reference_id | string | Yes | Your reference for the order. | 1–50 chars; letters, numbers and hyphens only (`ORDER-123456`, not `ORDER_123456`); unique across your orders. See [Duplicate requests](#duplicate-requests) |
| collection_mode | string | Yes | How the payment is collected. | `hosted_payment` or `s2s`; no default |
| mop_type | string | Conditional | Payment method. | Hosted Checkout: optional, one of `credit_card`, `debit_card`, `card`, `upi`, `net_banking`, `wallet`. `card` lets the buyer pay by credit or debit card, and needs card payments enabled on your account. S2S UPI Intent and Collect: required, `upi` |
| upi_flow_type | string | Conditional | UPI flow. | S2S: required. `intent` for S2S UPI Intent, `collection` for S2S UPI Collect; not case-sensitive. `collect` is refused |
| vpa | string | Conditional | The customer's UPI ID, which receives the payment request. | S2S UPI Collect: required. Lowercased, then must match `^[a-zA-Z0-9._]+@[a-zA-Z0-9.-]+$`, e.g. `john.doe@okaxis`. Ignored by the other flows |
| upi_expiry_minutes | integer | No | How long the customer has to complete an S2S UPI payment, in minutes. | S2S UPI Intent and Collect. Whole number from 5 to 20; omitted or `null` means 5. Some payment methods allow less than you ask for, so read the window that applies from `expires_at`. Ignored by Hosted Checkout |
| return_url | string | No | Where Hosted Checkout sends the customer when the payment finishes, whatever the outcome. | Absolute URL, max 500 chars. Without it the customer sees EximPe's own result page |
| business_model | string | No | Whether the buyer is a business or a consumer. | `B2B` or `B2C`, uppercase; derived from your KYC when omitted |
| purpose_code | string | No | FEMA/FETERS purpose code the order settles under. | Must be active and enabled on your account (e.g. `S0802`). When omitted, it is filled in only if your account has exactly one allowed purpose code |
| buyer | object | Yes | The buyer paying for this order. `name`, `email`, `phone` and `address` (including `postal_code`) are required. | See Buyer |
| product | object | Yes | What is being sold. | See Product |
| invoice | object | Yes | Invoice metadata. | See Invoice |

When you omit `purpose_code`, it is filled in only if your account has exactly one allowed code; otherwise it is left unset for later classification. Neither `business_model` nor `purpose_code` is returned by Create Order, and neither can be changed after the order is created. Read them back with [Get Order Details](/api-reference/v3/order/get).

#### Buyer

| Name | Type | Required | Description | Constraints |
|---|---|---|---|---|
| name | string | Yes | Full name. | Max 255 chars |
| email | string | Yes | Email address. | A valid email address |
| phone | string | Yes | Phone number with country code. | E.164: `+`, the country code, then the number, e.g. `+919812345678`; `9812345678` is refused |
| address | object | Yes | Address. | See Address |
| ip_address | string | Conditional | The customer's IP address. | S2S UPI Intent and Collect: required. IPv4 or IPv6 |
| user_agent | string | Conditional | The customer's browser user agent. | S2S UPI Intent and Collect: required |

| state | string | No | State. | Max 255 chars |

#### Product

| Name | Type | Required | Description | Constraints |
|---|---|---|---|---|
| name | string | Yes | Product or service name. | |
| description | string | No | Description. | Max 1024 chars |
| type_of_goods | string | Yes | Nature of what is sold. | `physical_goods`, `digital_goods` or `service` |

#### Invoice

| Name | Type | Required | Description | Constraints |
|---|---|---|---|---|
| number | string | Yes | Invoice number. | Max 255 chars. Letters, numbers, spaces and ``. , ' - / & _ ( ) : ; ! @ # $ % * + = < > [ ] { } \| ~`` — unlike `reference_id`, underscores are allowed. Unique across your orders that have not failed |
| date | string | No | Invoice date. | `YYYY-MM-DD` |

## Response

A successful create returns `201 Created`.

### Hosted Checkout

- `order_id`: The order's ID
- `session_id`: A 64-character hex string. Pass it to the EximPe JS SDK to open the payment page

<Warning>
  **The `session_id` is valid for 15 minutes.** After that, create a new order to get a fresh one. An expired or already-completed session returns `Invalid or expired session`.
</Warning>

### S2S UPI Intent

- `order_id`: The order's ID
- `intent_uri`: The UPI payment request to open the customer's UPI app with. See [Invoking the intent](#invoking-the-intent)
- `expires_at`: When the intent stops accepting payment, in UTC: `upi_expiry_minutes` after creation (5 minutes if you did not send it), or sooner if the payment method allows less
- `test_simulator_url`: **Sandbox only.** Open it in a browser to complete the payment without a real UPI app, and choose the outcome there. Where the page asks for a VPA, `testsuccess@gocash` succeeds and `testfailure@gocash` fails. Not returned in production

### S2S UPI Collect

- `order_id`: The order's ID
- `message`: Always `UPI Collection request sent`
- `expires_at`: When the request is set to expire, in UTC: `upi_expiry_minutes` after creation (5 minutes if you did not send it), or sooner if the payment method allows less

A `201` means the request reached the customer's UPI app, not that they have paid. There is no `intent_uri`: the customer approves the request in their UPI app, and you learn the outcome from the [Order Status API](/api-reference/v3/order/get-status) or the webhook. Use `expires_at` to tell the customer how long they have, not to decide the outcome: take that from the webhook or the Order Status API, which can report it some minutes after `expires_at`.

Sandbox responses may carry other testing fields. Ignore any field not listed here.

### Invoking the intent

Depending on how your account collects UPI, `intent_uri` comes either as a complete URI (`upi://pay?pa=...`) or as its query string alone (`pa=...&pn=...`). Handle both. For a QR code or the generic `upi://pay?` intent, use it as is if it starts with `upi://`; otherwise prefix it with `upi://pay?`. Never add a second scheme. For the Android `intent://pay?` and iOS app-scheme formats, use the query string only: strip a leading `upi://pay?` first. See the [integration guide](/integration-guide/v3/web-integration/s2s-upi-intent#step-3-invoke-upi-intent) for Android, iOS and desktop handling.

## Errors

Refusals use the standard envelope: `success` is `false`, and `error` carries a `code`, a `message` and `details`. A `400` carries `ERR_ORDER_002`: read `details` to see what failed and fix that field before retrying. An order declined by risk checks is a `400` with `ORDER_BLOCKED`; there is nothing to fix in the request.

| Status | `error.code` | When | `details` |
|---|---|---|---|
| `400` | `ERR_ORDER_002` | A field is missing or invalid | Keyed by field and nested like the request, one message per field, e.g. `{"buyer": {"phone": "Enter a valid phone number."}}` |
| `400` | `ERR_ORDER_002` | `reference_id` has a character other than a letter, number or hyphen | `{"reference_id": "Invalid input: ORDER_123456"}` |
| `400` | `ERR_ORDER_002` | `reference_id` is already used by one of your orders | `{"reference_id": "Reference ID already exists"}` |
| `400` | `ERR_ORDER_002` | `invoice.number` is already used by one of your orders that has not failed | `{"invoice": {"number": "Invoice Number already exists"}}` |
| `400` | `ERR_ORDER_002` | `collection_mode` is missing or unrecognised | `{"collection_mode": "Invalid collection mode"}` |
| `400` | `ERR_ORDER_002` | `business_model` is not `B2B` or `B2C` | `{"business_model": "\"b2b\" is not a valid choice."}` |
| `400` | `ERR_ORDER_002` | `purpose_code` is unknown or inactive | `{"purpose_code": "Invalid Purpose code given."}` |
| `400` | `ERR_ORDER_002` | `purpose_code` is valid but not enabled on your account | `{"purpose_code": "Purpose code is not enabled for this merchant."}` |
| `400` | `ERR_ORDER_002` | S2S `mop_type` is missing or not `upi` | `{"mop_type": "Invalid MOP type"}` |
| `400` | `ERR_ORDER_002` | Hosted Checkout `mop_type` is `card` and card payments are not enabled on your account | `{"mop_type": "CARD is not enabled for this account."}` |
| `400` | `ERR_ORDER_002` | `upi_flow_type` is neither `intent` nor `collection` | `{"upi_flow_type": "UPI flow type must be one of: INTENT, COLLECTION"}` |
| `400` | `ERR_ORDER_002` | S2S UPI Collect without `vpa` | `{"vpa": "VPA is required for collection flow"}` |
| `400` | `ERR_ORDER_002` | `vpa` is not a well-formed UPI ID | `{"vpa": "Invalid VPA"}` |
| `400` | `ERR_ORDER_002` | `upi_expiry_minutes` is below 5 or above 20 | `{"upi_expiry_minutes": "Ensure this value is greater than or equal to 5."}` or `{"upi_expiry_minutes": "Ensure this value is less than or equal to 20."}` |
| `400` | `ERR_ORDER_002` | `amount` is 0 or less, or above 10,000,000.00 | `{"total_amount": "Total amount must be greater than 0"}` or `{"total_amount": "Total amount must be less than or equal to 10,000,000"}` |
| `400` | `ERR_ORDER_002` | `currency` is not `INR` | `{"currency": "Unsupported currency"}` |
| `400` | `ORDER_BLOCKED` | The order was declined by EximPe's risk checks | `{"payment": "This payment cannot be processed. Please use a different payment method or contact the merchant."}` |
| `401` | `ERR_AUTH_000` | `X-Client-ID` or `X-Client-Secret` is missing | `{"authentication": "Missing credentials."}` |
| `401` | `ERR_AUTH_001` | The credentials are wrong | `{"authentication": "Invalid credentials."}` |
| `401` | `ERR_AUTH_000` | A PSP left out `X-Merchant-ID` | `{"authentication": "X-Merchant-ID header is required for this endpoint."}` |
| `401` | `ERR_AUTH_001` | `X-Merchant-ID` is not one of your active sub-merchants | `{"authentication": "Invalid X-Merchant-ID provided."}` |
| `403` | `ERR_MERCHANT_ACCOUNT_002` | Your merchant account is not active | `{"authentication": "Merchant account is inactive."}` |
| `403` | — | S2S payments are not enabled on your account | Not the standard envelope: `{"detail": "You do not have permission to perform this action."}` |
| `403` | `ERR_AUTH_005` | Your account's setup does not permit this collection mode | e.g. `{"collection_mode": "HOSTED_CHECKOUT is not enabled for this account."}` |
| `403` | `ERR_SERVICE_ERROR_000` | Your account is not configured to collect this way | e.g. `{"payment_gateway": "Payment gateway not configured"}` |
| `403` | `ERR_MERCHANT_ACCOUNT_003` | Your merchant account is suspended or closed | `{"merchant_account": "Merchant account is suspended."}` or `{"merchant_account": "Merchant account is closed."}` |
| `429` | `ERR_RATE_LIMIT_EXCEEDED` | EximPe or the payment network is rate limiting requests | Retry after the `Retry-After` header when it is present; otherwise back off and retry |
| `502` | `ERR_GATEWAY_UNAVAILABLE`, `ERR_PAYMENT_003` | S2S: the payment network could not be reached, or returned an error | Retry with a new `reference_id` |
| `500` | `ERR_SERVICE_ERROR_000` | Anything unexpected | `{"error": "An unexpected error occurred. Please try again later"}` |

## Duplicate requests

- **`reference_id` is single-use.** It must be unique across all your orders, whatever their status — a failed order still holds its `reference_id`. Sending one that is already used is refused with `Reference ID already exists`; the original order is not returned.
- **`invoice.number` is unique across your orders that have not failed.** Once an order fails, its invoice number can be used again.
- For a PSP, both rules apply per sub-merchant.

## After creating the order

- **Hosted Checkout.** Load the EximPe JS SDK on your page and call `eximpe.checkout({ sessionId })` within 15 minutes. The customer is sent to your `return_url` whether the payment succeeds, fails or is cancelled.
- **S2S UPI Intent.** Invoke the `intent_uri` on the customer's device before `expires_at`.
- **S2S UPI Collect.** Ask the customer to open their UPI app and approve the request. If they entered the wrong UPI ID, create a new order with a new `reference_id`.
- **Confirm the outcome from your backend.** Never trust the redirect or the UPI app alone: check the [Order Status API](/api-reference/v3/order/get-status) or wait for the [Payment Successful webhook](/api-reference/v3/webhooks/payment-successful).
