## Overview

Returns the values the sub-merchant dropdown fields accept: countries, nationalities, organisation types, monthly volume bands, and the business categories **your** account is approved for. Fetch it before you build a [Create Merchant](/api-reference/v3/merchant/create) request, and use the values exactly as listed.

```bash
curl 'https://api-pacb-uat.eximpe.com/partners/merchants/options/' \
  -H 'X-Client-ID: <client_id>' -H 'X-Client-Secret: <client_secret>' \
  -H 'X-API-Version: 3.0.0'
```

<Note>
  **Matching is case-insensitive; storage is not.** `india` and `INDIA` are both accepted for `India`, and `goods` for `GOODS`. This applies to countries, nationalities, organisation types, volume bands and business categories. The sub-merchant always stores and returns the listed spelling, accents included (`Curaçao`, `Burkinabé`); business categories are returned in upper case.
</Note>

HS codes are not listed here. There are thousands of them, so look them up with [Search HS Codes](/api-reference/v3/merchant/hs-codes).

## The response

| Name | Type | Used by |
|---|---|---|
| countries | string[] | `global_company.registered_country`, `global_company.communication_country`, `settlement_details.bank_country`, `beneficial_owners[].country_of_incorporation` |
| nationalities | string[] | `beneficial_owners[].nationality` |
| international_org_types | string[] | `global_company.international_org_type` |
| monthly_avg_transaction_volumes | object[] | `global_company.monthly_avg_transaction_volume`. Each entry has a `value` to send and a `label` to show. |
| business_categories | object[] | `global_company.business_category`. Only the categories your account is approved for. Each entry has a `value` to send, a `label` to show, and `requires_hs_codes`, which is `true` for goods categories. |

## Supported values

The lists below are the full set EximPe supports. The Get Merchant Options endpoint is the source of truth for accepted values; values are matched ignoring letter case. It is also the only place that shows which business categories you are approved for.

### Organisation types

For `global_company.international_org_type`. Eight values:

| Value |
|---|
| `Private Limited Company` |
| `Public Limited Company` |
| `Limited Liability Company` |
| `Joint Stock Company` |
| `Free Zone Company / Entity` |
| `Partnership / LLP` |
| `Sole Proprietorship` |
| `Other` |

### Monthly volume bands

For `global_company.monthly_avg_transaction_volume`. Seven values, in US dollars:

| Value | Meaning |
|---|---|
| `LESS_THAN_5_K` | Less than $5,000 |
| `BETWEEN_5_K_AND_20_K` | $5,000 - $20,000 |
| `BETWEEN_20_K_AND_50_K` | $20,000 - $50,000 |
| `BETWEEN_50_K_AND_100_K` | $50,000 - $100,000 |
| `BETWEEN_100_K_AND_250_K` | $100,000 - $250,000 |
| `BETWEEN_250_K_AND_500_K` | $250,000 - $500,000 |
| `ABOVE_500_K` | $500,000 & above |

### Business categories

For `global_company.business_category`. Send one or more slugs, comma-separated, e.g. `GOODS,SOFTWARE_CONSULTING`.

<Warning>
  **You can only use the categories your own account is approved for.** A sub-merchant's categories must come from the categories EximPe approved for you at onboarding. Any other slug is refused with a `400`, and so are labels and purpose codes. The `business_categories` list in the response above holds exactly your approved slugs. To add a category, contact EximPe.
</Warning>

A goods category (**HS codes required** below) needs at least one HS code in `global_company.hs_codes`. If no goods category is selected, leave `hs_codes` out.

If you select `OTHER` or `OTHER_B2B_SERVICE`, the sub-merchant takes the description you gave EximPe for your own "Other" category. There is no description field to send.

### Beneficial owner types

For `beneficial_owners[].type`:

| Value | Meaning |
|---|---|
| `INDIVIDUAL` | A person. Send `first_name`, `last_name`, `email`, `nationality` and `date_of_birth`. |
| `INSTITUTIONAL` | A company. Send `authorized_user_name` (the company's name), `country_of_incorporation` and `date_of_incorporation`. |

### Statuses

Returned in `status`. You cannot set it. EximPe's review sets it, and so does resubmitting through [Update Merchant](/api-reference/v3/merchant/update#resubmitting).

| Value | Meaning |
|---|---|
| `PENDING` | Submitted and waiting for review. |
| `IN_REVIEW` | EximPe is reviewing the application. |
| `CHANGES_REQUESTED` | EximPe needs changes before it can approve. |
| `APPROVED` | Active. You can collect for it. |
| `REJECTED` | The application was declined. |

### Sections

Returned in `section_reasons[].section` when EximPe asks for changes. Each value names the part of the application that needs attention:

| Value | Part of the application |
|---|---|
| `company_details` | Company details |
| `company_address` | Registered and communication addresses |
| `business_details` | Business details |
| `settlement_account` | Settlement bank account |
| `beneficial_owners` | Beneficial owners |
| `authorized_persons` | Authorised persons |
| `security_assessment` | Security assessment |

Every section except `authorized_persons` and `security_assessment` maps to fields you can change with [Update Merchant](/api-reference/v3/merchant/update). Those two cannot be fixed through the API; contact EximPe to resolve them.

## Errors

| HTTP | Cause | `code` | What to do |
|---|---|---|---|
| `401` | Missing or invalid credentials | `ERR_AUTH_000`, `ERR_AUTH_001` | Check `X-Client-ID` and `X-Client-Secret`. |
| `403` | Your account is not a PSP | `ERR_AUTH_003` | Only PSPs can manage sub-merchants. |
| `403` | Your account is a PSP, but not set up for import collections | `ERR_MERCHANT_017` | Contact EximPe. |
