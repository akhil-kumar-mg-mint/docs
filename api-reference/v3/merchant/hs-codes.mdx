## Overview

A sub-merchant with a goods category must declare at least one HS code in `global_company.hs_codes`, and each code must be one EximPe recognises. This endpoint searches that list by code or by description.

```bash
curl 'https://api-pacb-uat.eximpe.com/partners/merchants/hs-codes/?search=laptop' \
  -H 'X-Client-ID: <client_id>' -H 'X-Client-Secret: <client_secret>' \
  -H 'X-API-Version: 3.0.0'
```

Send the `value` of each code you pick in `hs_codes` on [Create Merchant](/api-reference/v3/merchant/create) or [Update Merchant](/api-reference/v3/merchant/update).

## Query parameters

| Name | Type | Required | Description |
|---|---|---|---|
| search | string | No | Text to match against the code and its description, e.g. `8471` or `laptop`. Leave it out to page through every code. |
| page | integer | No | Page number. Default `1`. |
| page_size | integer | No | Results per page. Default `250`, maximum `1000`. |

## The response

`data` is a page, with the same paging fields as [List Merchants](/api-reference/v3/merchant/list#the-response). Each result is one HS code:

| Name | Type | Description |
|---|---|---|
| id | integer | EximPe's ID for the code. |
| value | string | The HS code. Send this in `hs_codes`. |
| description | string | What the code covers. |
| policy | string | The import policy that applies to the code. Empty when none is recorded. |

## Errors

| HTTP | Cause | `code` | What to do |
|---|---|---|---|
| `401` | Missing or invalid credentials | `ERR_AUTH_000`, `ERR_AUTH_001` | Check `X-Client-ID` and `X-Client-Secret`. |
| `403` | Your account is not a PSP | `ERR_AUTH_003` | Only PSPs can manage sub-merchants. |
| `403` | Your account is a PSP, but not set up for import collections | `ERR_MERCHANT_017` | Contact EximPe. |
