---
title: 'List Settlement Documents'
description: "Every post-settlement compliance document attached to a settled B2B-services payment."
openapi: 'GET /pg/payments/{payment_id}/settlement-documents/'
---

## Overview

Once a B2B-services payment is **settled**, one more compliance step remains: evidence that the service was actually delivered. This endpoint reads what has been attached so far.

It is safe to call at any time — it reads, it never re-runs anything.

<Note>
  **B2B services only.** A payment that is not a B2B-services payment is refused. B2B goods has no partner-API settlement path.
</Note>

## Response

```json
{
  "success": true,
  "message": "Settlement documents",
  "data": {
    "documents": [
      {
        "document_id": "0f7c2a1e9b4d4c8e",
        "doc_type": "delivery_proof",
        "file_name": "delivery-note.pdf"
      },
      {
        "document_id": "3b91d5c7ae624f10",
        "doc_type": "delivery_proof",
        "file_name": "signed-acceptance.pdf"
      }
    ]
  }
}
```

An empty `documents` array means nothing has been attached yet — not that nothing is owed.

<ParamField path="document_id" type="string" required>
  Pass this to [Delete Settlement Document](/api-reference/v3/b2b/delete-settlement-document) while the submission is still a draft.
</ParamField>

<ParamField path="doc_type" type="string" required>
  B2B services has exactly one type, `delivery_proof`, and accepts **many files under it**. Goods is the opposite — one file per type — which is why the two flows do not share an endpoint.
</ParamField>

<ParamField path="file_name" type="string" required>
  The stored file's name, for display.
</ParamField>

## What is listed

Only **active** documents. A document you deleted is gone from this list and stays gone; deletion is a soft delete on our side, but there is no undelete through the API — attach the file again.
