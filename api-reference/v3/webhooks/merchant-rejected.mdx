## Event Overview

**Event Type**: `MERCHANT_REJECTED`  
**Category**: Onboarding  
**Description**: A sub-merchant's application has been declined

This webhook is sent when EximPe rejects a sub-merchant's application. It is delivered to the parent merchant's webhook URL. The sub-merchant's status is then `REJECTED`: it cannot collect payments and can no longer be edited.

It is sent once per rejection. A sub-merchant that is already `REJECTED` does not trigger it again.

A rejected sub-merchant can be removed with [Delete Merchant](/api-reference/v3/merchant/delete). To onboard the business again, create a new sub-merchant with [Create Merchant](/api-reference/v3/merchant/create).

## Field Specifications

<Tabs>
  <Tab title="Root Level Fields">
    <ParamField path="event_type" type="string" required>
      Always `"MERCHANT_REJECTED"` for this webhook event
    </ParamField>

    <ParamField path="event_time" type="string" required>
      UTC, no timezone suffix, e.g. `"2026-12-15T14:32:18.456789"`. Parse tolerantly — fractional seconds can be absent.
    </ParamField>

    <ParamField path="version" type="string" required>
      API version of your account, e.g. `"3.0.0"`
    </ParamField>

    <ParamField path="sequence_number" type="string" required>
      Unique ID of this event (a UUID, not an ordering counter). A retry resends the same value; use it to de-duplicate.

      **Example**: `"c81d4e2f-6b3a-4f9e-a5d7-0e1b2c3d4f5a"`
    </ParamField>

    <ParamField path="data" type="object" required>
      Event-specific data payload containing the rejection details
    </ParamField>
  </Tab>

  <Tab title="Data Object Fields">
    <ParamField path="data.merchant_id" type="string" required>
      Unique identifier of the rejected sub-merchant

      **Example**: `"1380229823"`
    </ParamField>

    <ParamField path="data.legal_name" type="string" required>
      Legal business name of the sub-merchant as registered with authorities

      **Example**: `"TechStore Solutions Private Limited"`
    </ParamField>

    <ParamField path="data.trade_name" type="string" required>
      The sub-merchant's brand name: the `brand_name` sent when it was created or last edited.

      **Example**: `"TechStore Online"`
    </ParamField>

    <ParamField path="data.timestamp" type="string" required>
      ISO 8601 timestamp when the application was rejected

      **Example**: `"2026-12-15T14:32:18.456789"`
    </ParamField>

    <ParamField path="data.reason" type="string" required>
      EximPe's reason for the rejection. Can be an empty string when no reason was recorded. The same text is returned as `reject_reason` by [Get Merchant](/api-reference/v3/merchant/get).

      **Example**: `"The business operates in a category EximPe does not support."`
    </ParamField>

    <ParamField path="data.section_reasons" type="array" required>
      One entry per part of the application EximPe flagged. Can be empty.

      - `section` — the part of the application, e.g. `"business_details"`. See [Sections](/api-reference/v3/merchant/options#sections) for every value.
      - `reason` — what EximPe found in that part.

      **Example**: `[{"section": "business_details", "reason": "Category is outside the supported list."}]`
    </ParamField>
  </Tab>
</Tabs>
